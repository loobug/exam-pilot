## 二、本轮验证发现并修复的问题

### 1. 题干被识别成页面标题（影响约 30% 的题）

**现象**：部分题的题干变成 `客户服务规范 2.0 · 模拟考试`，导致知识库匹配失败、降级给模型。

**原因**：`pickStem` 只按「文本最长」选题干，页面标题比短题干更长就赢了。

**修复**：加入语义加权——`h1~h6`、class 含 `stem/qtext/question` 的 ×1.6~2.2，以问号结尾 ×1.35，
与 `document.title` 相同或含「模拟考试/答题卡/倒计时」且短文本 ×0.12~0.25。

**验证**：题干与页面 `.qtext` 原文 **25/25 完全一致**（修复前 8/25 不一致）。

### 2. 判断题答案答反（选项被打乱时）

**现象**：题库答案 `A（正确）`，插件却填了「错误」。

**原因**：题库字母经映射成页面字母后，又被 `normalizeAnswer(judge)` 当成"标准顺序"转成对错，
而页面选项被打乱时 `B` 可能才是「正确」。

**修复**：判断题直接用**映射后的选项文本**（"正确"/"错误"）判对错，不再二次换算字母。

### 3. 知识库只靠 BM25 相似就直答，套错题

**现象**：命中「同一知识点的另一道题」，把它的答案套过来。

**修复**：直答需同时满足 ①题干精确命中 ②知识库选项与页面选项重合度 ≥ 0.5，否则降级为
「知识库+AI」或纯 AI。

### 4. 同题干多题（选项不同、答案不同）

**现象**：题库 #19（5 选项，答案 ABCD）与 #80（6 选项，答案 ABCDEF）题干完全相同，
检索总是拿到第一条。

**修复**：条目增加选项指纹 `optFp`，命中多条时按**选项重合度**选最匹配的那条。

## 四、验证方法的局限（须如实说明）

1. **模型答案质量无法用本地 mock 验证**。测试用 mock API 返回固定答案，只能证明
   「请求链路通」「答案解析正确」「填涂落地」，不能代表真实模型答对率。题库精确命中时
   不调用模型，这部分是确定性的；未命中时的准确率取决于你配置的模型。
2. **只覆盖了两种页面形态**：一屏一题（真实考试页）与一屏多题（demo）。其他站点若结构差异大，
   需要按其 DOM 补规则——`qxExtract.debugInfo()` 会给出每条路径的判定过程。
3. **Chrome 157 stable 不允许 `--load-extension`**，全部真机测试跑在 Chrome for Testing 上；
   手动装载走 `chrome://extensions/` 开发者模式，行为一致。
